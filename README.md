## Архитектурный контекст и решаемые задачи

При разработке интерфейсов управления системами хранения данных (СХД) и распределёнными кластерами критически важны:

1. **Производительность UI при работе с большими массивами данных:** В реальных инсталляциях счёт объектов (LUN, snapshot, targets, drive slots) идёт на тысячи. Обычный рендеринг такого объёма в DOM приводит к деградации FPS и задержкам отклика. В проекте реализован виртуализированный оконный рендеринг (windowed virtualization) с точечным обновлением состояния.
2. **Предиктивная валидация сложной доменной логики:** Конфигурирование отказоустойчивых пулов (RAID1/5/6, DDP) требует строгого соблюдения математических ограничений (минимальное число накопителей, чётность зеркалирования, политики Hot-Spare, LUN ID коллизии) ещё до отправки запроса на контроллеры.
3. **Наглядная визуализация аппаратной топологии:** Администраторам необходим прозрачный контроль над состоянием многопутевого ввода-вывода (ALUA), кэш-когерентности и состояния контроллеров при сбоях (failover).

## Стек технологий

- **Ядро:** React 18, TypeScript (режим `strict: true`)
- **Стейт-менеджмент:** Redux Toolkit (`@reduxjs/toolkit`, `react-redux`), мемоизированные селекторы `createSelector` (Reselect)
- **Сборка:** Vite 5, ESBuild
- **Тестирование:** Vitest (изолированное тестирование валидаторов и селекторов)
- **CI/CD:** GitHub Actions (автоматический запуск `typecheck`, `test` и `build` на каждый push и PR)

## Ключевые модули

```
src/
├── domain/storage/          # Изолированная бизнес-логика и доменная модель
│   ├── types.ts             # Строгие типы (Volume, Pool, Disk, ALUA, ClusterNode)
│   ├── validators.ts        # Чистые функции валидации и расчёта полезной ёмкости
│   ├── storageSlice.ts      # Redux-срез (фильтрация, сортировка, мастер пулов, failover)
│   ├── selectors.ts         # Мемоизированные селекторы метрик и агрегатов
│   └── mockData.ts          # Генератор 1200+ объектов инвентаря СХД
├── components/              # Презентационные и интерактивные UI-компоненты
│   ├── VirtualVolumeTable.tsx # Виртуализированная таблица томов с оверсканом
│   ├── PoolConfigurator.tsx   # Мастер дисковых групп с real-time проверкой правил
│   ├── ClusterTopologyMap.tsx # Интерактивная SVG-схема ALUA Multi-Pathing
│   ├── MetricsSummary.tsx     # KPI-карточки (IOPS, Latency P99, Overcommit Ratio)
│   └── Header.tsx
├── store/                   # Конфигурация Redux Store
├── App.tsx
└── main.tsx
```

## Инженерные практики

- **Чистые функции валидации:** Вся математика пулов вынесена в `validators.ts` и на 100% покрыта юнит-тестами.
- **Оптимизация рендеринга:** В таблице томов единовременно рендерится только видимая часть строк (~15–20 элементов из 1200+), что обеспечивает стабильные 60 FPS при быстром скролле.
- **Quality Gates:** Сборка проекта невозможна при наличии ошибок TypeScript или падении хотя бы одного юнит-теста.

## Локальный запуск и проверка

```bash
# Установка зависимостей
npm install

# Запуск dev-сервера
npm run dev

# Запуск набора юнит-тестов (Vitest)
npm run test

# Проверка типов TypeScript без сборки
npm run typecheck

# Продакшн-сборка
npm run build
```
